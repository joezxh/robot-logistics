## 第一部分：业务场景分析

### 1.1 系统定位

本系统定位为**复合型机器人仓储物流解决方案**，面向月台装卸、库内转运、仓储存取三大核心场景，实现货物从月台到仓储再到月台的全流程自动化作业。

**核心机器人形态**：双臂 AGV 装卸机器人——底部为差速驱动 AGV 底盘，上部搭载左右两个 6 轴机械臂（AUBO-i20），协同执行抱拿、搬运、放置货物任务。

### 1.2 功能域定义

| 功能域 | 核心功能 | 关键指标 | 当前实现状态 |
|--------|----------|----------|-------------|
| **装卸域** | 集装箱装卸、散货抱拿 | 节拍 ≤ 45s/托 | Phase 1 FSM 已实现 |
| **转运域** | AGV 自主导航、月台对接 | 响应 ≤ 30s | 底盘 HAL + diff_drive 已实现 |
| **仓储域** | 立库存取、平库管理 | 吞吐 ≥ 80托/小时 | 调度仿真已实现 |

### 1.3 流程关系

```
月台 ──► 装卸域 ──► 转运域 ──► 仓储域 ──► 转运域 ──► 装卸域 ──► 月台
 │         │           │           │           │           │
 └─────────┴───────────┴───────────┴───────────┴───────────┘
                          逆向流程
```

### 2.1 装卸机器人构型

系统核心设备为**双臂 AGV 装卸机器人**（`loading_robot`），物理构型如下：

```
           ┌──────────────┐
           │  左臂 (6-DOF) │   ┌──────────────┐
           │  AUBO-i20     │   │  右臂 (6-DOF) │
           │  arm_id=left  │   │  arm_id=right │
           └──────┬───────┘   └───────┬──────┘
                  │                    │
           ┌──────┴────────────────────┴──────┐
           │          躯干安装板               │
           │     (torso_mount, 固定关节)       │
           ├──────────────────────────────────┤
           │          AGV 底盘                │
           │   base_link (0.8×0.6×0.3m)      │
           │   left_wheel + right_wheel       │
           │   diff_drive_controller          │
           │   caster (万向轮)                │
           └──────────────────────────────────┘
                  抱板 (prismatic, 左右各一)
```

```
│   ├── planning/              # FK/IK/轨迹规划/插值器
│   ├── mqtt/                  # MQTT 适配器
│   ├── state/                 # 状态流/关节/位姿/错误

│   ├── robot_gateway/         # MQTT ↔ ROS 2 桥接
│   ├── robot_decision/        # 任务协调/运动规划/安全监控
│   ├── robot_arm_hal/         # 双臂 HAL（URDF + ros2_control）
│   ├── robot_base_hal/        # 底盘 HAL（URDF + diff_drive）
```

**依赖方向（强制）**：
- `shared/` 不依赖任何子项目

- `robot-app/` 依赖 `shared/` 和 `robot_arm_hal`
- `vla-training/` 独立，仅向 `robot_decision` 输出推理模型

### 3.3 通信契约

| 通道 | 方向 | MQTT Topic | QoS | 说明 |
|------|------|-----------|-----|------|
| 命令 | RCS → robot | `rcs/{device_id}/command` | 1 | 验证、排队、背压 |
| 状态 | robot → RCS | `rcs/{device_id}/state` | 0 | 降采样（10Hz） |
| 告警 | robot → RCS | `rcs/{device_id}/alert` | 1 | EventBus 事件 |
| 遥测 | robot → RCS | `robot/{device_id}/telemetry` | 0 | 电池/温度/连接 |

**命令类型**：

| 命令类型 | 用途 | 关键字段 |
|---------|------|---------|
| `move_j` | 关节空间运动 | `target_joints[]`, `speed_scale` |
| `move_l` | 笛卡尔空间直线 | `target_pose{x,y,z,rx,ry,rz}` |
| `execute_task` | 任务级命令 | `task_type`, `parameters`, `group` |
| `estop` | 急停 | 独立快速通路 |
| `stop` / `home` / `recover` | 调试直通 | — |

**任务级命令（execute_task）task_type**：

| task_type | 触发阶段链 | 执行器 |
|-----------|-----------|--------|
| `goto` | NAVIGATING | BaseExecutor |
| `pick_box` | APPROACHING → HUGGING | ArmExecutor + HugController |
| `place_box` | PLACING | ArmExecutor + HugController |
| `home_all` | RETREATING → IDLE | 全部执行器 |

### 3.4 TaskCoordinator 分层状态机

```
IDLE → NAVIGATING → DOCKING → APPROACHING → HUGGING → LIFTING
  → TRANSPORTING → PLACING → RETREATING → IDLE
任意状态 ──(超时/安全触发/RCS取消)──▶ ABORTING → IDLE
```

**派发规则**：
- NAVIGATING / TRANSPORTING / RETREATING → **BaseExecutor**（底盘航点）
- DOCKING / APPROACHING → **ArmExecutor**（双臂 MoveIt 规划）
- HUGGING → **HugController**（同步抱拿）
- LIFTING / PLACING → **ArmExecutor**（双臂 MoveIt 规划）

**实现约束**：
- 纯 Python，不依赖 rclpy（便于单测）
- 状态转换通过 `_VALID_TRANSITIONS` 字典约束
- 每阶段有可配置超时，超时触发 ABORTING

### 3.5 安全互锁（SafetyMonitor）

| 条件 | 约束 | 实现 |
|------|------|------|
| 底盘运动中 | 双臂必须收拢或抱紧 | `is_cmd_vel_allowed()` |
| 臂运动中 | 底盘速度强制 0 | `is_trajectory_allowed()` |
| 抱合中任一臂异常 | 双臂同步释放 + 整车停 | HugController.abort() |
| 急停触发 | 所有执行器立即停 | `trigger_estop()` → EMERGENCY |
| 雷达安全距离 | cmd_vel 直接拦截 | `update_scan(min_distance)` → SLOWDOWN |

**安全状态机**：`SAFE` ↔ `SLOWDOWN` → `EMERGENCY`（`reset_estop()` 恢复）

## 第四部分：操作流程与数据流

### 4.1 装卸任务全流程

```
RCS 下发 execute_task(task_type="pick_box")
         │
         ▼
robot_gateway (MqttBridge)
  ├─ decode_task_command() → TaskCommandMsg
  └─ task_sink → ~/task_command (JSON String)
         │
         ▼
TaskCoordinatorNode
  ├─ on_task_command() → TaskCoordinator.on_task_command()
  │
  │  Phase 1: NAVIGATING ──── BaseExecutor.follow_waypoint(x, y, yaw)
  │  Phase 2: DOCKING ─────── ArmExecutor.plan_and_execute(joints)
  │  Phase 3: APPROACHING ─── HugController.approach(target_pose)
  │  Phase 4: HUGGING ─────── HugController.close(pressure, speed)
  │  Phase 5: LIFTING ─────── ArmExecutor.plan_and_execute(joints)
  │  Phase 6: TRANSPORTING ── BaseExecutor.follow_waypoint(x, y, yaw)
  │  Phase 7: PLACING ─────── HugController.release()
  │  Phase 8: RETREATING ──── BaseExecutor.follow_waypoint(x, y, yaw)
  │
  └─ 每阶段完成 → advance_phase() → 发布 ~/robot_state
         │
         ▼
robot_gateway → MQTT → RCS (state/telemetry)
         │
         ▼
simulation/frontend: LoaderRobot 三维可视化 (SSE /api/devices/loader-01/joints)
```

### 4.2 数字孪生实时数据流

```
物理设备 / 仿真 ──► robot_gateway ──MQTT──► RCS
       │                                      │
       │ ~/robot_state                        │ state/telemetry
       ▼                                      ▼
  TaskCoordinator                     simulation/backend
  状态聚合发布                              Runtime 缓存
                                              │
                                              │ SSE /api/devices/{id}/joints
                                              ▼
                                    simulation/frontend
                                    Three.js 三维实时渲染
```

## 第六部分：安全与人机协作

### 6.1 安全系统分层

| 层级 | 措施 | 响应时间 | 实现状态 |
|------|------|----------|----------|
| 安全策略层 | 区域隔离/权限分级/应急响应 | — | 设计阶段 |
| 安全监控层 | 视频分析/区域入侵/异常行为 | ≤1s | Phase 2 |
| 主动防护层 | SafetyMonitor 互锁 + 雷达停障 | ≤50ms | Phase 1 已实现 |
| 本质安全层 | 力控限制/软限位/急停回路 | ≤10ms | Phase 1 急停已实现 |

### 6.2 已实现的安全机制

**SafetyMonitor**（`robot_decision/safety_monitor.py`）：
- 三态安全状态机：`SAFE` → `SLOWDOWN` → `EMERGENCY`
- 急停独立通路（不经过 TaskCoordinator），`estop_sink` 直达
- 命令速度拦截：`is_cmd_vel_allowed()` / `is_trajectory_allowed()`
- 雷达距离监控：`update_scan(min_distance)` 触发减速

**TaskCoordinator 安全特性**：
- 每阶段超时自动 ABORTING
- 任意阶段可触发 `abort(reason)` → ABORTING → IDLE
- 异常不传播（adapter 层 try/except）

### 6.3 人机协作模式

| 模式 | 场景 | 控制策略 |
|------|------|----------|
| 同空间协作 | 人工辅助抓取特殊货物 | 设备减速，实时避让 |
| 相邻空间分区 | 人工码垛 + 机器人搬运 | 物理隔离，正常速度 |
| 交替空间时序 | 人工装车 + 机器人备货 | 时序错开，区域锁定 |
| 监督模式 | 设备运行监控 + 异常处理 | 人工监督，自主运行 |

### 8.3 设计原则

1. **模块化**：四子项目解耦，依赖方向强制单向
2. **标准化**：JSON Schema 契约统一，MQTT Topic 规范
3. **智能化**：TaskCoordinator 9 阶段 FSM + VLA 推理（Phase 3）
4. **安全化**：SafetyMonitor 三级互锁 + 急停独立通路
5. **可视化**：Three.js 数字孪生 + SSE 实时关节数据
6. **柔性化**：Adapter 模式适配不同执行器，契约向后兼容
