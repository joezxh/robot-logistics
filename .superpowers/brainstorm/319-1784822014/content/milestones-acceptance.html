设计第 5 节：实现优先级、依赖、验收

M0–M1 起步 · 闭环 ≥ 90% · 验证脚本与代码同存并在 CI 内预验证。

A. 里程碑路线（依赖顺序）
M0
骨架
M1
机器人 / 仿真
M2
感知
M3
决策闭环
M4
Web Gateway
M5
演示验收

路径：URDF/SRDF → MoveIt 配置 → `ros2_control` → 相机 (arm_hal 已通) → 决策 → Gateway → Web → 验收。

B. 验收口径
里程碑验收脚本通过条件
M0verify_m0.sh空世界 + 核心话题
M1verify_m1.shhome → target → home（关节轨迹误差 ≤ ε）
M2verify_m2.shrosbag2 播放 → 检测与人工标注差 ≤ 阈值
M3verify_m3.shPickPlace 闭环 + Gazebo 回放
M4verify_m4.shFastAPI → Gateway → 设备 + UI 阶段
M5verify_m5.sh一键全链路 + 录像 + 验收单
C. 度量阈值
  • 闭环成功率 ≥ 90%（10 次 ≥ 9 次，CI 中自动跑 10 次）
  • 动作最长周期 ≤ 90 s
  • 急停 → 停机响应 ≤ 200 ms
  • WS 重连后 UI ≤ 2 s 对齐
D. 风险与回退
  • URDF/SRDF 与 MoveIt 不一致 → quick-disable collision
  • 感知误报 → 联立采样门控关闭感知
  • `ros2_control` 差异 → arm_hal 双实现
  • WS 失联 → UI “最近已知状态”快照
E. CI 集成
· 每里程碑 PR 必需通过 verify_*.sh · 闭环验证在 nightly 跑 10 次闭环，超过 20% 失败则回滚 · rosbag2 + 验收单同步归档到 artifacts/
最后汇总前需确认：
  1. 里程碑顺序与验收口径是否完整？
  2. CI 上夜间跑是否需要包含 M5 全链路（默认：包含，记录耗时）？
